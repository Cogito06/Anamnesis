# Anamnesis

> 柏拉图的「回忆说」：学习不是获取新知，而是回忆灵魂本已知道的东西。

让Agent和你一起学习，留下可以归档的记忆。
> Let's make some memories.

一款驱动学习的工具，为你的实践个性化定制“学习存档"。把你在对话里换来的理解——卡在哪、
误解是什么、怎么想通的——在 `/compact` 抹除它之前，化作永久的印记。

*A cross-session memory layer for learning with Agent. It captures the
cognitive trail of a study session — misconceptions, breakthroughs, open
questions — into greppable fragments that get re-injected when you come back.
Docs and prompts are in Chinese.*

---

## 问题

用 agent 辅助学 Math\Physics\CS 的时候，有价值的不是书上有的知识点，
而是**你卡在哪、为什么会那样想错、后来怎么想通的**。

但这部分理解只弥散在对话里。上下文一满，`/compact` 一跑，它就无影无踪了。
下次开会话，你和 agent 都得从头再解释一遍同样的概念。

## 它怎么工作

三个机制，接住问题的三个环节：

```
      你和 Agent 讨论
            │
    ┌───────┴────────┐
    │  触发          │  /cairn，或者上下文要满了它来提醒你
    └───────┬────────┘
            ▼
    ┌────────────────┐
    │  归档          │  筛掉书上有的 → 你过目 → 落盘 → 重建索引
    └───────┬────────┘
            ▼
      cairn/  ← 长在你的学习仓库里，跟着 git 走
            │
    ┌───────┴────────┐
    │  唤回          │  下次开会话，索引和欠着的问题自动回到桌上
    └───────┬────────┘
            ▼
      不用第二次解释同一件事
```

**工具装在 `~/.claude/`，记忆长在你的仓库里。** 一次安装，多少门课都行，
每门课的记忆跟着自己的仓库走——能 commit，能换机器，能分享。

## 安装

```bash
git clone https://github.com/Cogito06/Anamnesis.git
cd Anamnesis && ./install.sh
```

需要 `bash` 和 `python3`（只用标准库）。安装会把 skill、图谱工具和三个 hook
放进 `~/.claude/`，并**先备份**你原有的 `settings.json`。

## 用法

在学习仓库里开会话，打 `/cairn`。第一次它会问要不要初始化。

之后每聊完一个主题打一次：

1. 它回顾整场对话，把书上查得到的筛掉
2. **列一张提议表，此时一个字都不写盘** —— 你砍、你改、你补
3. 你点头，才落盘、才重建索引

下次开会话，索引和所有还欠着的问题会自己回到桌上——你不用记得去查。

## 一条真实的片段

下面这条来自 cs170，**原样搬来**，只省略了 insight 段末尾的一张附表。

````markdown
---
course: cs170
cluster: 复杂度从哪来
date: 2026-09-15
concepts: [整数乘法, integer multiplication, 点值表示, Karatsuba, FFT, 主定理]
hook: Karatsuba 把 a 从 4 掰到 3 但够不到平衡点 a=b^d=2，所以永远叶重；FFT 落在边界不是因为切得巧，是因为它换了表示法
refs:
  - slides/lec-2_full.pdf
---

## 触发

学完主定理，拿它回头看上一轮的整数乘法讨论
（[[change-model-vs-change-algorithm]]），把 Karatsuba 和 FFT 的 (a,b,d) 摆进天平里。

## 卡点 / 误解

**我原以为** Karatsuba 和 FFT 是「同一条路上走得更远」，FFT 只是切得更聪明。

不是。三个参数里能调的只有一个——`b=2`（对半切）和 `d=1`（合并的加减法）
被问题本身钉死了，唯一的杠杆是 `a`：

```
                      a   b   d   log_b a          结果
朴素分治乘法          4   2   1   2        叶重   n²
Karatsuba             3   2   1   1.585    叶重   n^1.585
──── 平衡点 a = b^d = 2 ────────────────────────────  ← 够不到
FFT                   2   2   1   1        边界   n log n
```

**所以顺着 Karatsuba 这条路走，永远走不出 n log n。**

## 关键 insight

FFT 落在边界，不是因为切得更聪明——**它根本没在切同一个问题**，
它换了表示法（系数 → 点值，卷积变成逐点乘）。

这给 [[change-model-vs-change-algorithm]] 的二分补了一层：
换表示法不是第三条路，是「改算法」里最激进的一种。

## 遗留问题

- [ ] a 只能取整数，log_b a 却连续扫过所有实数——「刚好落在边界」是巧合，还是有更深的原因？
````

三个地方值得留意：

- **那张天平表在打仗，不是配图。** 「够不到平衡点」这个结论直接从表里读得出来。
  删掉表，论断就退化成一句要人相信的话
- **`卡点` 写的是错误信念本身**，不是正确答案。正确答案书上有，
  「我为什么会那样想错」只有这里有
- **`[[链接]]` 就长在提到它的那句话旁边。** 这些链接会织成一张图

索引里它被压成一行，`hook` 就是破折号后那句：

```
- [karatsuba-cant-reach-balance] 整数乘法/integer multiplication/点值表示/Karatsuba/FFT — Karatsuba 把 a 从 4 掰到 3 但够不到平衡点 a=b^d=2，所以永远叶重；FFT 落在边界不是因为切得巧，是因为它换了表示法 | open:1 | 09-15
```

索引不手写，由脚本从片段推导。手写迟早漏条目，而漏掉的那条会**悄无声息地**
从检索里消失——片段还在磁盘上，却再没人找得到。

## 知识图谱

![350 个片段的知识图谱](docs/graph-overview.jpg)

```bash
python ~/.claude/anamnesis/graph/graph.py cairn
```

生成 `cairn/graph.html`。**单文件、零外部依赖、离线可用**，双击就开。

图能看见索引看不见的四件事：

- **哪些板块是孤岛** —— 和谁都不连，说明那块知识还没接进来
- **哪些板块之间只有一根线** —— 那根线往往就是理解刚打通的地方，画成虚线标为「桥」
- **哪些片段谁也不认识** —— 孤儿被推到边缘
- **哪些片段你知道该写、却还没写** —— 指向不存在片段的链接画成淡色幽灵

最后一条借自 Obsidian。死链在这里不是错误，是一个**念头**：你写下
`[[还没写的片段]]`，说明你已经知道那儿该有东西。它和孤儿正好成对——
孤儿有内容没连接，幽灵有连接没内容。

### 悬停任一节点

![聚焦到一个枢纽节点](docs/graph-focus.jpg)

它和它的邻居留在前景，其余退到背景。上图是 350 个片段里度数最高的那个枢纽。
点一下还会开详情面板：钩子、欠着的问题、材料、以及可以继续跳的链接。

颜色只给最大的三个板块，其余中性灰。**这不是偏好，是算出来的**——
节点图里任意两簇都可能挨在一起，第四个色相（黄↔橙）色盲对比度过不了线。
身份靠标签承载，颜色从不单独说话。

节点大小、标签显不显示、边有多透明，全由同一个量决定：**每个节点在屏幕上分到多少地方**。
6 个片段和 350 个片段共用一套参数，不用手动调档。

## 几条原则

**质控闸门比触发时机重要。** 书上查得到的一律只存指针。索引是常驻的，
每混进一条教科书摘要，你以后每一轮对话都为它付钱，而它的检索价值是负的。

**不把触发绑在 compact 上。** compact 的边界是随机的，会把话题从中间劈开；
那一刻 Agent 的上下文也最满、状态最差。所以主力是你手动打的 `/cairn`，
hook 只当闹钟。

**注入索引，不注入内容。** Agent 看一行钩子自己决定要不要展开。
比向量检索稳——选择过程看得见，召回错了你也看得见。

**不动你的学习材料。** 课程仓库用它自带的骨架，`cairn/` 是唯一的新增物。
hook 靠魔术标记判断要不要启动，**在非学习项目里完全静默**。

## 现在做到哪

| 机制 | 状态 |
|---|---|
| 触发 | 建成 |
| 归档 | 建成 |
| 唤回 | **一半** |
| 图谱 | 建成 |

索引本身就是检索——它有概念词、有钩子句，Agent 读着它做匹配，而且是语义的，
比字面搜还灵。缺的不是「检索」，是三件更具体的事：

**索引只是 11% 的摘要。** 一条片段 2725 字节，进索引的那行只有 292 字节。
「卷积」「逐点乘」「二分查找」这些词在片段正文里出现了十几次，
索引里**一次都没有**。你要是问「卷积和乘法什么关系」，索引一个字都匹配不上，
可正文里讲得清清楚楚。命中率的天花板，是当初写钩子时恰好想到了什么。

**长列表下注意力会衰减。** 6 行必然看见，300 行（约 12k token）就未必。
grep 不会。

**没有东西强制它去搜正文。** Agent 可以 grep，但没人要求它；
索引看起来没货时，它通常就不找了。

**而且失败是无声的。** 你只会觉得这次回答一般，永远不知道本可以更好。

补法（提问时匹配全文、派子 Agent 去读候选片段）都得等真实数据——
片段少于 20 条时，子 Agent 是负收益，主 Agent 直接开文件更快更准。
