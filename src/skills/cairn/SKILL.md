# Cairn —— 垒一块路标

把本次会话里**值得未来的用户看到**的东西，写成片段存进 `cairn/`。

石堆不是地图。它不告诉你全貌，只在你可能走错的岔路口说一句「这边」。
片段也一样：它不复述教科书，只标记用户摔过的那个坑。

## 第 0 步：确认这是一个 cairn 仓库

检查当前工作目录下 `cairn/INDEX.md` 是否存在、首行是否为 `<!-- cairn:v1 -->`。

**不存在** → 问用户「这个文件夹还不是 cairn 仓库，要初始化吗？」。
同意后只创建这两样：

```
cairn/
├── INDEX.md        # 首行 <!-- cairn:v1 -->，第二行 # Cairn Index，其余交给脚本
└── fragments/
```

**不要重排或改动仓库里任何已有的文件和目录。** 用户的学习仓库用的是课程自带的骨架
（`slides/ hw/ lab/ proj/` 之类），那个结构是他熟悉的，`cairn/` 是唯一的新增物。

## 第 1 步：回顾并筛选

回看本次会话，列出候选片段，然后逐条过**质量闸门**：

| 情况 | 处理 |
|---|---|
| 内容在课程材料 / 教科书里查得到 | **存指针，不存内容**——写进 `refs`，正文不复述 |
| 既没有卡点、也没有 insight | **丢弃**，不要为了凑数留 |
| 只是复述了你（agent）给出的正确答案 | **丢弃**，那是你的输出，不是用户的认知轨迹 |

留下的每条都要能回答：

> 三个月后的用户读到它，会得到什么书里没有的东西？

答不上来就丢掉。这道闸门是整个系统能否长期可用的关键：索引是常驻上下文，
每混进一条教科书摘要，未来每一轮对话都要为它付 token，而它的检索价值是负的——
它会挤掉真正有用的条目，让人不如直接翻书。放水一次，信噪比就永久降一格。

**最有价值的素材依次是**：卡住又解开的地方、被推翻的误解、书上没写的跨章节连接、
用户自己的记号约定、还没搞懂的问题。

### 例子：留哪些，丢哪些

例子不是插图，好的例子在**承担论证**。判据是它有没有在证明什么：

**留下**

- **判决性实例**——杀死那个误解的那一个。比如「27 → 13 → 6 → 3 → 1 → 0，5 轮」
  这几个数字本身就是对「log n 层」的反驳；删掉它，论断退化成一句要人相信的口号
- **最小可复现案例**——现象出现的最小规模
- **用户自己手算过的那个**——带着他的数字，是绑在他记忆上的检索线索，
  和教科书里任何例子都不等价

**丢掉**

- 教科书的标准例题 → 存 `refs` 指针
- 已经有一个之后的第二个（27×19 之后的 12×34 是冗余的）

例子**内嵌在它支持的那段里**（`卡点` 或 `关键 insight`），不要单开一节。
例子不是一项独立职责，它是某个断言的证据；单开一节会制造一个需要填的格子，
然后你会为了填它去找例子——那正是「凑数」这个失败模式。

## 第 2 步：提议，不要写盘

把筛选结果列成表，**此时一个文件都不要创建**：

```
建议归档 N 条：

1. [slug] 标题
   卡点：（一句话）
   insight：（一句话）
   钩子：（准备写进索引的那句话）
   遗留：（如果有）

已丢弃 M 条：（各一句话说明理由，让用户有机会捞回来）
```

然后停下等用户砍、改、补。这一步不能省——用户对自己认知轨迹的判断比你准，
而且他记得哪些是真卡过、哪些只是顺口聊到。你从对话记录里分不出这个差别。

## 第 3 步：落盘

用户确认后，按 `${CLAUDE_SKILL_DIR}/assets/fragment-template.md` 的结构写入
`cairn/fragments/<slug>.md`。

### 命名：slug 即身份

**文件名就是 id 就是链接名，一个字符串处处相同。**

```
文件名   halve-is-not-log.md
链接     [[halve-is-not-log]]
索引     [halve-is-not-log]
```

日期存在 frontmatter 的 `date` 字段里，**不进文件名**。日期是元数据不是身份——
让它参与身份的唯一后果是写链接时得先回忆日期，而那正是出错的地方。

三条规则：

1. 全小写，短横线连接，只用 ASCII 字母数字
2. **写成一句断言的骨架，不是名词短语**——`halve-is-not-log`，
   不是 `russian-peasant-complexity`。片段存的是「误解 → 纠正」，
   slug 就该是那个纠正的缩写
3. 2–5 个词

**撞名了不要加后缀。** slug 撞说明是同一个主题，该合并成一条；
加 `-2` 只会造出两条互不知道对方存在的片段。

### frontmatter 五个字段

没有 `id`（文件名即是），没有 `status`（`open:N` 已经表达了）。
冗余字段迟早会和真相漂移。

- `course` —— 日后按学科分化 agent 的切分依据
- `date` —— 元数据
- `concepts` —— **按检索概率降序排列**，索引只取前 5，排序规则见下
- `hook` —— 索引里唯一显示的那句话
- `refs` —— 指向课程材料，可带 `#锚点`

**concepts 的排序规则**（因为索引只取前 5，排在后面的进不了索引）：

1. 用户未来最可能拿来搜它的词——通常是中文主概念 + 它的标准英文名
2. 专有名词、算法名（Karatsuba、Four Russians）——独特，检索命中率高
3. 泛化的类别词（渐近复杂度、分治）放最后——它们会匹配太多片段，反而是噪声
4. hook 句里已经出现过的词往后排，索引行里重复它没有价值

### 写作要求

- **用用户自己的话和记号**，不要改写成教科书腔。他认得出自己的语言，认不出百科腔
- `concepts` 中英术语都写，否则 grep 会漏
- `卡点 / 误解` 要写清楚**错误的想法本身**，不只是正确答案。复用价值全在这里——
  正确答案书上有，而「我为什么会那样想错」只有这里有
- `hook` 是索引里唯一显示的那句话，认真写。它要让未来的 agent 判断
  「该不该展开读这个片段」：写「共形映射的性质」是失败的钩子，
  写「以为能简化任意 PDE，实际只对 Δu=0 有效」才是
- 遗留问题用 `- [ ]` 前缀，脚本和 hook 都靠它识别

### 片段之间用 [[slug]] 链接

相关的片段互相引用，**内嵌在提到它的那句话旁边**，不要单列「相关片段」一节：

```markdown
真正的突破要等分治，见 [[change-model-vs-change-algorithm]]。
```

这些链接会长成一张图，映射出用户理解之间的实际结构——哪些概念在他脑子里是连着的。

**索引按 `cluster` 字段分簇**：同一板块的片段写同一个名字，例如
`cluster: 整数乘法能多快`，索引里就带标题成组显示。留空的归到「尚未归簇」。

**簇的边界必须是声明的，不能从链接图推。** 一度试过用连通分量自动推导成员，
但**跨簇链接是正常且值得鼓励的**——「Karatsuba 够不到平衡点」理应链向
「改模型 vs 改算法」——而只要有一条这样的边，两个簇就塌成一个。
实测 6 条片段被并成 1 个大簇，一学期下来会塌成一团。

图现在用来找异常和找桥：声明成同一簇却互不链接会报警告；
**跨簇的链接会被单独报出来**，因为那是理解之间的连接，往往是最有价值的部分。

**分簇不是合并的替代品，两者解决不同问题。** 该不该把几条片段合成一条，判据是
能不能写出一个仍然具体的 hook；写不出就别合——钩子一模糊，这条片段就永远不会被打开，
每轮付常驻成本却从不被检索，比分开更糟。分簇让它们在索引里显示成一个板块，
但每条保留自己那个具体的钩子。

`rebuild_index.py` 会校验死链并报告孤儿片段（没有任何进出链接的那些）。
孤儿通常意味着这块知识还没接进用户已有的理解网络，值得提一句。

## 第 4 步：重建索引

**跑脚本，不要手写索引**：

```bash
python ${CLAUDE_SKILL_DIR}/scripts/rebuild_index.py cairn
```

索引是片段的纯派生物。手写迟早会漏条目，而漏掉的那条会**静默地**从检索里消失——
片段还在磁盘上，但没人再找得到它。让脚本从磁盘重新推导，这种错误就不可能发生。

脚本会重排序、重算 `open:N`、统计链接数，并报告：缺字段、不合规范的文件名、
死链、悬空的 `refs`、孤儿片段、以及索引常驻量是否超标。**把警告念给用户听**，
悬空 refs 可能是有意的占位（指向还没读到的章节），由用户确认。

## 第 5 步：报告

告诉用户：新增几条、索引现共几条、当前未解决问题几个、脚本报了哪些警告。

如果这次有片段的遗留问题被解决了，提醒用户回去把那条 `- [ ]` 改成 `- [x]`
并重跑脚本——未解决问题列表每次开会话都会注入，留着已经解决的会稀释它，
而且列表有 30 条上限，堆积会把新问题挤出去。
